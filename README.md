# Локальный лор

Версия 1.1.0. Показывает, какие записи лорбуков попадут в ближайший ответ: постоянные, по ключу, из чьего сообщения и сколько примерно токенов они займут. В промпт расширение ничего не дописывает. Книги по-прежнему подключает сам клиент.

Из кода расширения наружу ничего не уходит. Кнопка обновления в Таверне — это её собственный `git pull` этого репозитория, не запрос из панели лора.

## Установка в SillyTavern

Таверна предлагает обновление только если расширение поставлено из git. Папка, скопированная руками, кнопки не получит: у неё нет удалённого репозитория, и проверка считает её актуальной.

1. Открой SillyTavern.
2. Сверху нажми «Расширения» (Extensions).
3. Внизу панели выбери «Установить расширение» (Install extension).
4. Вставь адрес `https://github.com/Prohor-godslayer/local-lore`.
5. Ветку оставь `main`. Если спросят, для кого ставить, оставь текущего пользователя.
6. Подтверди установку и дождись перезагрузки интерфейса.
7. Открой «Управление расширениями» (Manage extensions). Карточка называется «Локальный лор», версия 1.1.0.
8. Включи «Уведомлять об обновлениях расширений» (Notify on extension updates), если такая галочка есть.

Открытие: кнопка ⊹ у края чата (её можно перетащить; место запоминается в этом браузере), пункт «Локальный лор» в меню расширений, Esc или крестик закрывают панель.

Если раньше папка уже лежала в `data/<пользователь>/extensions/local-lore` без git, удали её и поставь по ссылке заново. Иначе Таверна не с чем сравнивать версию.

### Когда Таверна говорит, что нужно обновить

В `manifest.json` стоят `"version": "1.1.0"` и `"auto_update": true`. При проверке Таверна делает `git fetch` и сравнивает твой коммит с `origin/main`. Если на GitHub есть коммиты новее, у карточки появляется кнопка. В английской сборке она подписана **Update available**. В русской подпись берётся из языкового пакета Таверны, это перевод той же строки. Нажми кнопку: Таверна выполнит `git pull` и перезагрузит расширение. Новый номер версии смотри в той же карточке.

Проверка вручную: Расширения → Управление расширениями → карточка «Локальный лор».

## Установка в Tavo

1. Открой на GitHub папку `tavo` и скачай `local-lore.tpg`. Прямая страница файла: https://github.com/Prohor-godslayer/local-lore/blob/main/tavo/local-lore.tpg — кнопка загрузки исходного файла.
2. В Tavo импортируй этот `.tpg` как плагин.
3. Сетевого разрешения у плагина нет. Нужны сообщение, переменные и файл.
4. Панель открывается кнопкой ⊹, действием ввода «Локальный лор» и пунктом боковой панели.

Tavo сам git не тянет. Новую версию ставь повторным импортом свежего `.tpg`. Номер в манифесте плагина — 1.1.0.

## Как пользоваться

1. Привяжи лорбук к чату обычным способом клиента или положи книгу в карточку персонажа.
2. Открой панель и нажми «Обновить». Список строится заново при новом сообщении, пока панель открыта.
3. Сверху видно, сколько записей активно, примерную цену в токенах, сколько записей появилось или пропало с прошлого обновления и глубину сканирования. Глубина в Таверне берётся из настройки World Info, иначе 4 сообщения.
4. Группы списка:
   - Постоянные — записи с флагом constant.
   - Сработало — ключ совпал, в том числе `@@activate`.
   - Вытеснены группой — ключ был, но в группе победила запись с большим весом.
   - По смыслу — векторные записи. По ключам их предсказать нельзя, это так и подписано.
   - Почти — основной ключ есть, вторичная логика не пустила.
   - Молчат — совпадений нет.
   - Выключено — запись выключена или стоит `@@dont_activate`.
5. Нажми строку. Будут ключи, вторичные ключи, кусок текста, где совпало, и сама запись.
6. «Книги» сужает набор. Пустой выбор значит «все, что клиент отдал». «Считать все» снимает фильтр. Выбор хранится в файле этого чата.
7. Поиск фильтрует уже построенный список по имени, книге и ключу.
8. «Отчёт» копирует активные записи в буфер. Если буфер недоступен, панель так и напишет.

Целое слово включено только у записей, где оно включено в книге. «чай» тогда не цепляет «чайник». Без этого флага ищется подстрока. Шанс записи показывается в процентах и в расчёт «сработало» не бросается: кубик всё равно кинет сам клиент в момент ответа.

Книга в карточке читается и как список, и как словарь записей. Учитываются поля `key` / `keys`, `keysecondary` / `secondary_keys`, `enabled`, `disable`, `insertion_order`.

## Где лежат данные

SillyTavern: фильтр книг и прошлый набор сработавших id — в метаданных чата, ключ `local_suite.lore`. Общие настройки расширения — в `settings.json`, ключ `local_suite_lore`.

Tavo: тот же смысл в файле плагина `lx_lore_chatbag`, с запасным путём через глобальную переменную и `localStorage`.
